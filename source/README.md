# Парсер таблицы -> data.js

Скрипт `../parse.js` читает экспорт Google Таблицы `source/sheet.html`
и генерирует базу изделий `../data.js` (`const DATA = [...]`).
Чистый Node.js, внешних зависимостей нет.

## Как обновить данные

1. Открой исходную Google Таблицу.
2. `Файл` -> `Скачать` -> `Веб-страница (.html)`.
3. Замени файл `source/sheet.html` на скачанный (то же имя).
4. Запусти из корня проекта:
   ```bash
   node parse.js
   ```
5. Прочитай отчёт `source/parse-report.txt` и проверь предупреждения
   ПЕРЕД тем как использовать новые данные.

`data.js` перезаписывается автоматически. Ручные правки в нём будут потеряны.

## Как парсер находит столбцы

Столбцы ищутся по ТЕКСТУ ЗАГОЛОВКА (первые ~12 строк сетки). Если заголовок
не найден, используется резервный индекс (см. таблицу) и в отчёт попадает
предупреждение. Это защита от сдвига/вставки столбцов в таблице.

| Поле        | Ожидаемый заголовок (вхождение)      | Резерв. idx | Колонка |
|-------------|--------------------------------------|-------------|---------|
| product     | Изделие                              | 0           | A       |
| parts       | перечень деталей                     | 14          | O       |
| fileName    | Название файла                        | 15          | P       |
| machine     | номер станка                         | 16          | Q       |
| distance    | Расстояние между головами             | 17          | R       |
| heads       | количество голов                     | 20          | U       |
| abTime      | время резки                          | 27          | AB      |
| time        | Итого время на файл                  | 29          | AD      |

idx — нумерация с 0 по колонкам в `<tbody>`.

## Что считается строкой-данных

Строка — данные, только если одновременно:
- `Название файла` непустое И
- `номер станка` — число.

Это отсекает легенду (цветовые подписи), многоуровневые заголовки и строки
«Итого ...» с пустым именем файла.

`rowspan`/`colspan` разворачиваются в прямоугольную сетку, поэтому «Изделие»
(у него `rowspan` на весь блок) «протягивается» на каждую строку изделия.
Если имя изделия пустое — берётся предыдущее (carry-forward).

## Какие поля обязательны (иначе строка ПРОПУСКАЕТСЯ)

1. Изделие (product) — непустая строка.
2. Название файла (fileName) — непустая строка.
3. Голова (heads) — целое И равно 2 или 4 (иначе пропуск: ошибка таблицы).
4. AB-гейт: столбец «время резки» (AB) должен быть > 0. Пусто/0/нераспознано
   -> строка пропускается (считается в отчёт как AB-гейт, НЕ как ошибка).
5. Расстояние — строгое число. Пробелы внутри (напр. `45 800,00`), буквы,
   лишние символы = БРАК -> строка пропускается с предупреждением.
6. Итоговое время (AD) — при прошёдшем AB-гейте должно распарситься в > 0,
   иначе пропуск с предупреждением.

`перечень деталей` (fileDescription) НЕ обязателен: пустое -> `"не указано"`.
Неверное/пустое описание НЕ приводит к пропуску записи.

## Как формируются данные

Изделие -> файлы (детали) -> по каждой корзине голов `"2"` и `"4"` хранится
`{ distanceCm, timeSec }`.

- Если в таблице нет данных для какой-то корзины голов -> она заполняется
  `{ distanceCm: 0, timeSec: 0 }` (0 = данных нет, типы не ломаем).
- Одинаковые файлы внутри одного изделия объединяются по имени.
- Коллизия (одно `файл+голова`, но разное расстояние/время) — оставляется
  ПЕРВОЕ корректное значение, событие пишется в отчёт.
- Описание (fileDescription): берётся ПЕРВОЕ непустое значение среди строк
  файла; расхождения описаний пишутся в отчёт как «Инфо».

Время — в секундах (удобно умножать на повторы и суммировать по станку).
`кол-во повторов` намеренно НЕ хранится — это переменная ввода оператора.

## Отчёт source/parse-report.txt

После каждого запуска парсер пишет отчёт:

- Определение столбцов (где нашёл/фолбэк).
- Счётчики (строки, изделия, файлы).
- Пропуски строк-данных по причинам (AB-гейт, голова, расстояние, время).
- Коллизии file+heads (оставлено первое).
- Предупреждения (подозрительные значения, брак расстояния и т.п.).
- Инфо (разные описания у одной детали).

Если в отчёте появились предупреждения/коллизии — проверь исходную таблицу
(возможна опечатка) прежде чем доверять данным.
